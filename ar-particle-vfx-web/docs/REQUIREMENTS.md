# AR 手势粒子交互 - 网站落地需求文档

## 一、文档说明

本文档定义「基于 Web 摄像头的手势 AR 粒子交互」网站的落地需求，包括项目背景、功能需求、非功能需求、交互设计、界面设计与验收标准，作为开发与验收的依据。

---

## 二、项目背景

### 2.1 项目目标

构建一个纯网页端应用，用户通过浏览器授权电脑摄像头后，系统实时识别手部关键点，并驱动粒子系统产生视觉反馈，实现无外设的 AR 手势粒子交互体验。

### 2.2 目标用户

- 浏览器用户（Chrome / Edge 最新版）
- 具有电脑摄像头的桌面端用户
- 对 AR 交互、手势识别感兴趣的演示/体验用户

### 2.3 项目价值

- 零安装、零外设的 AR 交互体验
- 展示 MediaPipe + Three.js 的前端技术能力
- 可复用到游戏、展示大屏、互动装置等场景

## 三、功能需求

### 3.1 核心功能

| 编号 | 功能 | 优先级 | 描述 |
| --- | --- | --- | --- |
| F01 | 摄像头采集 | 必须 | 调用浏览器 getUserMedia 获取视频流 |
| F02 | 手势识别 | 必须 | MediaPipe 识别 21 个手部关键点 |
| F03 | 粒子渲染 | 必须 | Three.js 渲染发光粒子系统 |
| F04 | 手势-粒子联动 | 必须 | 手势驱动粒子运动效果 |
| F05 | 多手势支持 | 必须 | 至少支持张开/捏合/抓握 3 种 |
| F06 | 双手识别 | 可选 | 同时识别 2 只手 |

### 3.2 手势与粒子交互定义

| 手势 | 触发条件 | 粒子响应效果 |
| --- | --- | --- |
| 张开（OPEN） | ≥4 指尖远离手腕 | 粒子向手部位置吸引，形成光晕 |
| 捏合（PINCH） | 拇指尖与食指尖靠近 | 粒子向指尖强汇聚，形成高亮核心 |
| 抓握（GRAB） | ≥4 指尖靠近掌心 | 粒子围绕手掌旋转成漩涡 |
| 挥手（移动） | 手部快速位移 | 粒子产生拖尾效果 |
| 无手势（NONE） | 未识别到上述手势 | 粒子自然漂浮、缓慢扩散 |

## 四、非功能需求

### 4.1 性能需求

| 指标 | 要求 | 说明 |
| --- | --- | --- |
| 帧率 | ≥ 30 FPS | 桌面端持续运行 |
| 识别延迟 | < 100 ms | 手部动作到粒子响应 |
| 粒子数量 | ≥ 5000 不卡顿 | 本机可支撑更高 |
| 启动时间 | < 3 秒 | 页面加载到可交互 |

### 4.2 兼容性需求

| 项目 | 要求 |
| --- | --- |
| 浏览器 | Chrome 最新版、Edge 最新版 |
| 操作系统 | Windows / macOS / Linux 桌面端 |
| 网络 | 需 HTTPS 或 localhost 安全上下文 |
| 摄像头 | 需浏览器可访问的摄像头 |

### 4.3 可用性需求

| 项目 | 要求 |
| --- | --- |
| 摄像头权限引导 | 拒绝授权时给出明确提示 |
| 错误提示 | 摄像头不可用/浏览器不支持时友好提示 |
| 降级方案 | 无摄像头时可切鼠标交互 |

### 4.4 安全与隐私需求

| 项目 | 要求 |
| --- | --- |
| 数据本地处理 | 摄像头画面不采集、不存储、不上传 |
| 用户授权 | 严格遵循浏览器权限机制 |
| 隐私 | 无任何用户数据外送 |

## 五、交互设计

### 5.1 用户流程

```
打开网站
  ↓
浏览器请求摄像头权限
  ├─ 允许 → 进入手势交互主界面
  └─ 拒绝 → 显示引导提示（如何开启摄像头）
        ↓
伸出手到摄像头前
  ↓
系统识别手势 → 粒子产生对应效果
  ↓
用户切换手势 → 粒子效果实时切换
```

### 5.2 交互细节

| 场景 | 交互反馈 |
| --- | --- |
| 页面加载 | 显示「请授权摄像头，然后伸出手」提示 |
| 摄像头授权成功 | 提示切换为手势说明文案 |
| 手部进入画面 | 粒子开始响应手部位置 |
| 手势切换 | 粒子效果实时改变 |
| 手部移出画面 | 粒子恢复自然漂浮状态 |
| 初始化失败 | 显示具体错误信息 |

| 元素 | 规范 |
| --- | --- |

## 八、验收标准

### 8.1 功能验收

| 验收项 | 标准 |
| --- | --- |
| 摄像头启动 | 授权后视频流正常，无报错 |
| 手势识别 | 张开/捏合/抓握均能正确识别 |
| 粒子联动 | 不同手势产生对应的粒子效果 |
| 双手识别 | 两只手同时识别（可选） |

### 8.2 性能验收

| 验收项 | 标准 |
| --- | --- |
| 帧率 | ≥ 30 FPS（DevTools Performance 面板） |
| 延迟 | < 100 ms（肉眼观察无明显滞后） |
| 粒子数 | ≥ 5000 粒子不卡顿 |

### 8.3 兼容性验收

| 验收项 | 标准 |
| --- | --- |
| Chrome / Edge | 正常运行 |
| localhost / HTTPS | 摄像头权限正常 |

### 8.4 健壮性验收

| 验收项 | 标准 |
| --- | --- |
| 拒绝摄像头权限 | 显示友好提示，不崩溃 |
| 无摄像头设备 | 显示明确错误信息 |
| 网络异常（CDN 不可用） | wasm 本地化后不受影响 |

## 十、范围与约束

### 10.1 范围内

- 桌面端浏览器运行的 AR 手势粒子交互
- 张开/捏合/抓握三种基础手势
- 单手优先，双手可选

### 10.2 范围外（本期不做）

- 移动端适配优化
- 复杂手势（如数字手势、自定义手势）
- 深度相机真 3D 交互
- 后端服务与用户账号体系
